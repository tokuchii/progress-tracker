# Fix PDF export: overlapping / misaligned text

## Problem
The "Export PDF" output shows overlapping and misaligned text (per user's screenshot).
The export lives in `app/utils/notepad.ts` → `exportQuestionsPdf()`, called from
`app/pages/dashboard.vue` → `exportPdf()`.

## Root causes (confirmed by reading jspdf source)
1. **Prefix width measured under the wrong font.**
   `jspdf` `getTextWidth()` uses the *currently active* font (last `setFont` call),
   and `setFontSize()` does not reset the style. In the block loop,
   `prefixWidth = doc.getTextWidth(prefix)` runs while the font is whatever the
   previous token left it as (bold from the title, or the last word's style).
   The prefix is then drawn in `'normal'`, so the number/bullet width no longer
   matches and the text that follows is horizontally misaligned (gaps / overlap).
   The pre-refactor code did `doc.setFont('helvetica','normal')` before measuring
   the prefix width — this was accidentally dropped in the rewrite.
2. **Highlight rectangles overlap adjacent lines.**
   `doc.rect(x, y - fontSize*0.85, width, fontSize*1.2, 'F')` produces a 13.2pt-tall
   box anchored to an 11pt baseline, and `lineHeight` is only 6.5pt. Adjacent
   highlighted lines' rects merge and later rects paint over the previous line's
   text, reading as "overlapping" content.
3. **Line spacing too tight.**
   `lineHeight = 6.5` with an 11pt font makes consecutive lines visually collide
   even without highlights, and is far from the editor's airy 28px line-height.

## Changes (single file: `app/utils/notepad.ts`)
In `exportQuestionsPdf()`:

1. **Reset font state before measuring prefixes.**
   - After the title, set `doc.setFont('helvetica', 'normal')`.
   - Before `prefixWidth = ... getTextWidth(prefix)`, explicitly
     `doc.setFont('helvetica', 'normal')` so the measured width matches the
     drawn prefix.

2. **Tighten the highlight box to the text line.**
   - Change to `doc.rect(x, y - fontSize * 0.8, width, fontSize, 'F')`
     (≈ from `y - 8.8` to `y + 2.2`), hugging the glyphs instead of spilling
     into neighbours.

3. **Increase line height.**
   - `const lineHeight = fontSize * 1.2` (≈ 13) instead of `6.5`, so lines and
     highlights no longer collide. Keep it a single named constant so it is easy
     to tune.

No other files change. List markers, indentation, bold/italic/underline/
strikethrough, color, and the member-question text already export correctly and
are unchanged.
